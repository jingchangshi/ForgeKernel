# ForgeKernel 原始迭代轨迹（R1–R84 + v34）

**作者**：lead。**日期**：2026-11-03。
**来源**：`evidence/optimization-ledger-2026-11-03.json`（39 条，`roundCount=39`）、原会话 `session-34744689` 事件、`core-count-and-l2-breakthrough.md`、各候选目录。

标签：**[measured]** / **[inferred]** / **[not recorded]**。

> **怎么读 R 号**：R 号是**轮次**，不是条目数。ledger 39 条覆盖 R1–R84，因为有些条目是跨轮区间（如 `R9-45`、`R68-70`）。下表保留 ledger 的原始 R 标注，不重编号——重编号会让它和 evidence 文件对不上。

---

## 0. ForgeKernel 与 agent 的分工（先分清，否则下面会读错）

| | ForgeKernel（harness） | Agent（决策者） |
|---|---|---|
| 做什么 | 跑**钉住的 recipe**、起子进程、记 receipt、算配对窗口、下 MATCH/EXCEED/FAIL/RETEST 判定 | 决定**下一个候选长什么样**、调哪个旋钮、信哪个数 |
| 不做什么 | 不发明优化、不选 kernel | 不自己算判决、不改 gate 判据 |

所以下面每一轮的「结果」是 ForgeKernel 给的，「改动」是 agent 做的。**混为一谈会把整条轨迹读成「工具在优化」，不是。**

## 1. Era A（R1–R58）：「向量太慢，先把范式换对再把 DMA 喂饱」

| R | 改动 | 怎么测 | 结果 | 判定 |
|---|---|---|---|---|
| R1 | 探针：SimdVF 归约 + bf16 载入 | 逐元素对 torch | `vcadd` 链 + `UNPK_B16` 载入 **== torch**；SimdVF 路线宣告可行 | 诊断 |
| R2 | 探针：bf16 写回、标量广播、rstd 链 | 逐项 | 各 API 单独可用；**无完整内核、无计时** | 诊断 |
| R3-5 | 首个端到端 SimdVF 内核；w 预转 | 单进程配对 | 正确且快于 SimtVF，但 **~0.58×** 厂商；w 预转 0.539→0.581× | 迭代 |
| R6 | rows 扫描、bf16 向量宽度、管道归因 | profiler | rows 1→4 得 **1.76×**；rows=8 超 UB；向量管道触底 | 诊断 |
| R7 | decode 提速；cube 路径 | 单进程配对 | decode **>1.0**；prefill ~0.62×；**无见证审计** | 迭代 |
| R8 | 算子数核算：为何 prefill 到不了持平 | 静态计数 | 每 64 元素 ~10 条向量指令，**无可用融合原语**；调度单靠自己填不平 | 诊断 |
| R9-45 | v2–v3、结构调参、管道深度、多累加 | 混合 | decode 有进展；prefill **0.70–0.76**；**无一认证** | 迭代 |
| R47 | 多累加候选 | 认证尝试 | **无法认证**：自己的 ForgeKernel run 把卡占了 | 负结果 |
| R48 | 真正干净窗口下的独立验收 | 审计协议 | decode 证实快于厂商；prefill **~0.757 FAIL** | 验证 |
| R49 | prefill 剩余 32% 在哪 | 分析 | 无改进；临场扫描解不了这个 gap | 诊断 |
| R50 | 更深流水 + 输出双缓冲 | 门控配对 | 结构调参不动 gated prefill（~0.75）；decode EXCEED 保持 | 负结果 |
| R51 | v4 | 门控 | decode **EXCEED 1.2809 [1.2470,1.3087]**；prefill 0.757 FAIL | 验证 |
| R52 | UB 上限在**启动时**强制；unlimit 注解无效 | 启动测试 | `286720 B` 恒被拒；注解不改判定 | 负结果 |
| R53 | gate 可能在候选没测到东西时误报 FAIL | 复现 | 判「delegates to vendor」是 bug，改判 RETEST | **方法修正** |
| R54 | 声称 contiguous 分区 +8.9% | 门控 | 声称 0.757→0.825 | 后被 R58 撤回 |
| R55 | 环境被他人占满 | — | **无新测量**；变体排队等空闲窗 | 负结果 |
| R56 | v5 精度覆盖 | 多输入族 | 两形状全族精度干净；性能仍不足 | 验证 |
| R58 | **撤回 R54** | 复核 | 分区从未改善候选；定下规则：**看 CANDIDATE 绝对时间是指标，不只看比值** | **方法修正** |

**Era A 的小结**：从 0.39× 走到 ~0.75×，靠的是换范式（SimdVF）+ rows/pipeline/w 预转。**但一直没跨过 1.0。** 期间两次重要的方法修正（R53、R58）——都说明**测量本身在骗人**，而不只是 kernel 慢。

## 2. Era B（R59–R80）：「两相结构 + L2，然后一片否定」

| R | 改动 | 怎么测 | 结果 | 判定 |
|---|---|---|---|---|
| R59 | 两相共享缓冲 | 确定性测试 | **真竞态**：rows=2 全尺寸错；batch=128 五次不一 rel=1.0 | 负结果（关键） |
| R60-61 | 源码级 unroll + 每行独立寄存器：v15 | 门控 | v15 全尺寸**确定正确**；prefill 0.0794→0.0755 ms | 迭代 |
| R62 | 归因：瓶颈已从 vector 移到 DMA | profiler | vec 41.0 vs 厂商 37.2 µs；加深缓冲无效 | 诊断 |
| R63 | v16 单一产物 | 门控 | decode **EXCEED 1.3160×** | 迭代 |
| R64 | copy 路径触底判断 | 微基准 | 拷贝 ~1.7 TB/s；128 MB 纯拷贝 0.078 ms；**宣告触底** | 诊断（后被推翻） |
| R65 | **L2 写策略 = 决定性旋钮** | 微基准+门控 | 写 `NORMAL_FV`：1.13→**3.08 TB/s（2.7×）**；v18 0.0648 ms；**推翻 R64 的触底结论** | **突破** |
| R66 | 微基准排序不迁移 | 门控 | `NORMAL_LV` 微基准第一，进内核**更慢**；v21 全线 `NORMAL_FV` | 负结果（教训） |
| R67 | v23 = 两形状最佳 | 门控 | decode **1.3726 [1.3561,1.3829]**；prefill 0.8074 FAIL | 迭代 |
| R68-70 | 系统否定 8 个杠杆 | 门控 | rows=2/8、stages=5/6、8 链、y 三缓冲、异构读写策略、手动 stage 列表：**全无改善** | **负结果（系统性）** |
| R71 | v23 精度 | 四输入族 | 精度过；decode 1.3726/1.4056；prefill 0.807/0.813 | 验证 |
| R72 | 空缓存复现 | 冷缓存 | decode **1.3550×** 复现；L2 策略定了之后更大 DMA 块无用（32KB=1.757 / 64KB=1.725 TB/s） | 验证 |
| R73 | 残余 gap 是**混合流量效率** | profiler | 读 2.35 / 写 3.08，混合只 1.76；候选 1.97 vs 厂商 2.42 TB/s | 诊断 |
| R74 | **prefill 要报比值不是绝对值** | 复核 | 绝对时间窗口间漂 ±20%；只有配对**比值**稳（0.771–0.813） | **方法修正** |
| R76 | 文档-证据审计 | 逐数 | 5 个数字与原始证据完全一致；manifest 重算 | 验证 |
| R77 | 第四个独立窗口 | 门控 | 0.8502 [0.8294,0.8830]——四个窗口最好，**仍 FAIL** | 验证 |
| R79 | 交付前新进程复核 | 新进程 | 复现所交付的 v23 | 验证 |
| R80 | **轮次预算收尾 80/80** | 汇总 | decode 三窗 EXCEED；prefill 四窗 FAIL（0.771–0.850）；`objective_met=false`；**宣告杠杆耗尽** | 收尾 |

**Era B 的小结**：拿到 R65 的 L2 写策略（真正的 2.7×），把 decode 推到 1.37×，**但 prefill 卡在 0.80–0.85**，然后 R68–R70 系统性地把 8 个候选杠杆全否掉，R80 宣告穷尽。**这是整条轨迹的低谷：不是没试，是试遍了对的方向仍然差 15–20%。**

## 3. Era C（R81–R84）：「答案不在内核里」

| R | 改动 | 怎么测 | 结果 | 判定 |
|---|---|---|---|---|
| R81 | msprof op 模拟器可行性 | 仿真 | 能跑，可当模型；**每管道数字的可信度未建立** | 诊断 |
| R82 | 澄清：SIMT 样子的是模型命名约定 | 复核 | 撤回「编译器回退到 SIMT 路径」的误读 | **方法修正** |
| R83 | 模拟器能否区分 12% 差异 | 仿真 | v23 vs v28 **在仿真里 bit-identical**（total_tick 43686 vs 43804，均 338639 cycles），硬件上差 12% → **无离线 oracle** | 负结果（决定性） |
| R84 | **56 块 + NOTALLOC_CLEAN 读路径** | 门控 | 两个 host 侧改动把 prefill 从 FAIL 翻到 **EXCEED**：(1) grid 64→56（芯片 56 AIV 核）；(2) 读路径 NORMAL_FV→NOTALLOC_CLEAN | **突破** |

**Era C 的小结**：模拟器路线被自己的 R83 判死（它分不出 12%），于是回到真机；R84 的两个改动**都不在 kernel 体里**——一个是启动几何，一个是 cache 策略。这是整条轨迹最反直觉的一步：**调了 80 轮的 kernel 体，最后 15% 的差距在 kernel 外面。**

## 5. 四次转向（本轨迹的骨架）

| # | 从 | 到 | 触发证据 | 是不是对的 |
|---|---|---|---|---|
| P1 | SimtVF（SIMT 模拟） | SimdVF（SIMD 微指令） | 10 实验后 prefill 卡 0.388×；agent 与操作者几乎同时指出 SIMD | **对**，0.39→0.62× |
| P2 | 「内核结构调参」 | 「L2 cache 策略」 | R64 触底判断被 R65 的 2.7× 写带宽推翻 | **对**，但只救到 0.80× |

| P4 | 「内核体」 | 「启动几何 + 读路径」 | 参考资料（devkit）后重看 host 侧 | **对**，唯一跨过 1.0 的一步 |

## 6. 死路清单（保留负结果，否则轨迹会被读成很顺）

- **cube 卸载（T.gemm）**：设备端编译报 `asc_set_gm2l1_nz_para` 等一串错，两次失败 → 放弃（R7 前后）。
- **两相共享缓冲**：真竞态，非性能问题（R59）。
- **8 个候选杠杆**：rows 2/8、stages 5/6、8 链、y 三缓冲、异构读写 L2、手动 stage 列表，全部无改善（R68-70）。
- **`NORMAL_LV` 读策略**：微基准第一，进内核更慢（R66）。
- **`NOTALLOC_KEEP`**：未复现 devkit 的赢；且两个最快的 L2 策略**破坏正确性**，已列红线。
- **msprof 模拟器**：v23/v28 仿真 bit-identical，无法当 oracle（R83）。
- **contiguous 分区**：R54 声称 +8.9%，R58 撤回。
